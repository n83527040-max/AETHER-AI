Step 1 · Choose where Hermes runs

AETHER's client is Flutter on Android. The agent runtime is a separate long-lived Hermes gateway. GitHub Actions was the requested host — research shows it fits the 6-hour ceiling but not GitHub's terms of service for interactive workloads.

Policy finding (GitHub Terms, effective 2026-08-27). For GitHub-hosted runners, Actions may not be used for "any other activity unrelated to the production, testing, deployment, or publication of the software project associated with the repository where GitHub Actions are used." The same document also forbids using Actions "as part of a serverless application". An always-interactive personal agent is unrelated activity; enforcement can include job termination, Actions restriction, repository disabling, or account suspension.

Step 2 · GitHub App or GitHub OAuth App?

Both can sign a user in. They differ in how much access they request, how long tokens live, and whether access is limited to selected repositories.

Evidence-based comparison

CriterionGitHub AppOAuth App
Permission modelPer-resource (Contents, Actions, Metadata)All-or-nothing classic scopes
Repository scopeInstallation can be limited to selected reposEvery private repo the user can access
User token lifetime8 h + 6-month refresh tokenNon-expiring unless enabled
Short-lived repo tokenYes — 1 h installation tokenNo
Mobile sign-in without secretDevice flow (client_id only)Device flow (client_id only)
Browser redirectPKCE S256 supportedPKCE S256 supported
Token exchange/refreshNeeds client secret → brokerNeeds client secret → broker (or re-auth)
Create a repositoryNeeds "Administration" write (broad) — avoid; use a pre-filled github.com/new linkNeeds repo
Dispatch a workflowActions (write)repo + workflow
RevocationUninstall app, or revoke one tokenRevoke token
Setup effortHigher (installation + broker)Lower
Why the recommendation stands. AETHER stores encrypted snapshots and dispatches orchestration workflows. That calls for Contents and Actions write on one chosen repository, not blanket control of every private repository. A GitHub App expresses exactly that and can be revoked per installation.

Step 4 · Create the application

Follow these steps exactly. Values in monospace come from the fields you filled in.

  1. Open the GitHub App creation form. github.com/settings/apps/new (personal) · org owners: https://github.com/organizations/<ORG>/settings/apps/new
  2. Name and home page. App name: AETHER AI. Homepage URL: your repo or product page (HTTPS).
  3. Identifying and authorizing users. Leave the callback URL blank if you chose device flow. For browser redirect, set:
    aetherai://oauth/callback
    Then tick Enable Device Flow if you chose device flow.
  4. Webhook. Untick Active unless you explicitly enabled webhooks in Step 3. If you did, paste the webhook URL and secret.
  5. Repository permissions. Set exactly the permissions in the table below. Leave everything else at No access. Do not grant Administration.
  6. Account permissions. None.
  7. Subscribe to events. None for v1 (polling).
  8. Where can this app be installed? "Only on this account" for personal use; "Any account" only if you intend to distribute AETHER.
  9. Create the GitHub App, then copy the App ID and Client ID into Step 3.
  10. Generate a client secret (App settings → Client secrets → Generate). Put it in your broker environment, never in this page's export.
  11. Generate a private key (App settings → Private keys → Generate a private key). A .pem downloads once. Store it on the broker host with 0600 permissions. GitHub cannot show it again.
  12. Install the App on your account and choose Only select repositories → your AETHER workspace repository. Copy the installation ID from the URL (/installations/<ID>).
  13. Verify least privilege. Re-open the app settings and confirm no extra permissions were granted.
  1. Open the OAuth App form. github.com/settings/applications/new · org: https://github.com/organizations/<ORG>/settings/applications/new
  2. Application name: AETHER AI. Homepage URL: HTTPS product or repo page.
  3. Authorization callback URL: aetherai://oauth/callback — must match the app's deep link exactly.
  4. Register application, then copy the Client ID into Step 3.
  5. Generate a client secret and store it in your broker environment.
  6. Enable Device Flow in the app's settings if you selected device flow.
  7. Review scopes. OAuth Apps request classic scopes at authorization time; keep them to repo, workflow, read:user.
  8. Verify the app's callback URL and homepage are correct, then test authorization with a throwaway account.

Callback URL rules. GitHub compares the callback literally. Every environment (debug/release) needs its own registered URL or scheme host. A custom scheme like aetherai://oauth/callback is acceptable for a native app; an HTTPS App Link to your broker domain is stronger because Android verifies domain ownership, but requires assetlinks.json hosting.
