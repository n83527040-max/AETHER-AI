# AETHER AI — GitHub App configuration checklist
### Print this, or use `docs/setup/aether-setup-console.html` for the interactive version.

Configuration values are **never** invented. Everything below is collected from you or generated by GitHub after you create the app.

---

## 0. Decisions to confirm first

- [ ] Runtime hosting: **A1 dedicated compute** (recommended) / A2 self-hosted / A4 Termux / A3 hosted Actions (requires risk acceptance)
- [ ] GitHub identity: **B1 GitHub App** (recommended) / B2 OAuth App
- [ ] Sign-in flow: **F1 device flow** (recommended) / F2 browser + PKCE
- [ ] Key custody (B1 only): **C1 token broker** (recommended) / C2 device-flow only

---

## 1. Create the GitHub App

Open **https://github.com/settings/apps/new**
(organization: `https://github.com/organizations/<ORG>/settings/apps/new`)

| Setting | Value to enter | Notes |
|---|---|---|
| GitHub App name | `AETHER AI` | Your choice; must be globally unique |
| Description | `Your Personal Autonomous AI Agent` | Public |
| Homepage URL | your repo or product URL | Must be a valid URL |
| Identifying and authorizing users → Callback URL | blank for device flow; otherwise `aetherai://oauth/callback` or `https://<broker-host>/oauth/callback` | Must match exactly |
| Enable Device Flow | ✅ if using F1 | Required for device flow |
| Webhook → Active | ❌ off (default) | Only enable if you chose webhooks |
| Repository permissions → Metadata | Read | Mandatory |
| Repository permissions → Contents | Read & write | Snapshots + config |
| Repository permissions → Actions | Read & write | Orchestration workflows only |
| Repository permissions → Workflows | Read & write | Update workflow files on upgrade |
| All other repository permissions | No access | Including **Administration** |
| Account permissions | None | |
| Subscribe to events | None | Polling is used in v1 |
| Where can this app be installed? | Only on this account (personal) | "Any account" only for distribution |

- [ ] App created
- [ ] **App ID** copied (numeric, public)
- [ ] **Client ID** copied (public)
- [ ] **Client secret** generated → stored in broker env only (**secret**)
- [ ] **Private key** generated → `.pem` saved to broker host, `chmod 600` (**secret**)
- [ ] App installed → **Only select repositories** → workspace repo
- [ ] **Installation ID** captured from `https://github.com/settings/installations/<ID>`

## 2. Verify the configuration (real API calls)

```bash
export GH_APP_ID="<your app id>"
export GH_APP_PRIVATE_KEY_PATH="/secure/path/aether-app.private-key.pem"
bash docs/setup/verify-github-app.sh
```

Expected output:

- `App identity: <slug> (id <n>)` — the App ID and private key match.
- `Installations: <id> → <account> (selected repositories)` — installation exists.
- `Installation token: minted (expires in 60 minutes)` — key can mint tokens.
- `Repository access: <owner>/<repo>` — Contents permission reaches the workspace repo.

If you see `401`, the App ID/private key pair is wrong. If you see `404` on repositories, the app is not installed on that repository.

## 3. OAuth App equivalent (only if you chose B2)

Open **https://github.com/settings/applications/new**

| Setting | Value |
|---|---|
| Application name | `AETHER AI` |
| Homepage URL | your repo/product URL |
| Authorization callback URL | `aetherai://oauth/callback` |
| Client ID | public — copy to app config |
| Client secret | **secret** — broker env only |
| Enable Device Flow | ✅ if using F1 |
| Scopes | `repo`, `workflow`, `read:user` |

> OAuth Apps have no installation model: the token covers **all** private repositories the user can access. This is why the GitHub App is recommended.

## 4. Values classification

| Value | Class | Where it goes |
|---|---|---|
| App ID / Client ID / App slug | Public | App config + manifest |
| Callback URL / installation ID | Public | GitHub settings, broker config |
| Client secret | **Secret** | Broker env |
| Private key `.pem` | **Secret** | Broker filesystem, 0600 |
| Webhook secret | **Secret** | Broker env (only if webhooks) |
| Provider API keys | **Secret** | Worker env / device Keystore |
| GitHub user & installation tokens | **Short-lived** | Memory + Android Keystore |

## 5. Safety rules

- Never commit a secret. Never paste one into chat.
- Keep `.env` git-ignored; commit only `.env.example` with empty placeholders.
- Rotate the client secret and private key if either is exposed.
- Revoke access by uninstalling the App; tokens die within 8 h (user) / 1 h (installation).
- Repository deletion is not requested. Creating a repository is a user action via `github.com/new` with prefilled name, verified by the app afterwards.
